# Trace ingest protocol v1

This is the normative contract between an SDK and a Trace server for sending Events. The server and every SDK implement this document. [`event.schema.json`](event.schema.json) is its JSON Schema (2020-12), and [`fixtures/`](fixtures/) holds the conformance fixtures that the server's tests and the SDKs' tests both load.

The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are to be read as in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

## Versioning

v1 only grows additively: a new optional field, a new error code, a new allowed value. An incompatible change goes to a new endpoint, `/api/ingest/v2`.

- The server MUST ignore unknown fields, at every level of the body.
- The server MUST be strict on types and required fields: a field of the wrong type, or a required field that is missing, rejects the Event.
- Field names are case-sensitive. A case variant of a known field, such as `Level`, is an unknown field, so it is ignored.
- An SDK MUST NOT send `null`. The server treats `null` as an absent field, so a `null` in a required field rejects the Event.

## Endpoint

```
POST /api/ingest/v1/events
```

The Project is the one that owns the Ingest Key. The URL holds no Project id.

## Authentication

The SDK sends the Ingest Key of its Project in the `X-Trace-Ingest-Key` header. When it cannot set headers, as with `navigator.sendBeacon`, it MAY send it in the `ingest_key` query parameter instead. The key MUST NOT go in the body. An Ingest Key is not a secret: it ships inside the host application.

- If both the header and the query parameter are present with different values, the server responds `400 ingest_key_conflict`.
- If the key is absent, the server responds `401 ingest_key_missing`; if it is unknown or revoked, `401 ingest_key_invalid`. In both cases the server responds without reading the body.

## Content type, encoding and CORS

- `Content-Type` MUST be `application/json` or `text/plain`. Both carry a JSON body. `text/plain` lets a browser send without a CORS preflight.
- The body MAY be compressed with `Content-Encoding: gzip`. No other encoding is supported.
- Any other `Content-Type` or `Content-Encoding` gets `415 unsupported_media_type`.
- The server answers `OPTIONS` preflights and every response with `Access-Control-Allow-Origin: *` and without `Access-Control-Allow-Credentials`. The SDK MUST NOT send credentials.

## Size limits

The server rejects bodies over the limits with `413 payload_too_large`. It never truncates them, and it stops reading as soon as a limit is exceeded.

| What | Limit |
| --- | --- |
| Body as sent (compressed, if gzip) | 256 KiB |
| Body after decompression | 1 MiB |
| One Event, serialized | 128 KiB |

## Batch

The body is a JSON object with one field, `events`, an array of 1 to 100 Events:

```json
{"events": [{"event_id": "…", "…": "…"}]}
```

The batch is all or nothing. If any Event is invalid, the server rejects the whole batch with `400 invalid_event`, stores nothing, and lists each invalid Event in `details` with its `index` in `events`, counted from 0. A body that is not such an object, or an `events` array that is empty or holds more than 100 Events, also gets `400 invalid_event`, with empty `details`.

## Event

Lengths count characters (Unicode code points), except for `extra`, which counts the bytes of its serialized JSON. The SDK SHOULD trim values to fit these limits before sending, because the server rejects an Event that exceeds them.

### Required fields

| Field | Type | Rules |
| --- | --- | --- |
| `event_id` | string | A UUID in canonical form (8-4-4-4-12 hex digits, any case), generated by the SDK. v7 is preferred. |
| `timestamp` | string | When the Event happened, by the client clock: an RFC 3339 date in UTC, ending in `Z` or `+00:00`, with a fraction of 3 to 9 digits, such as `2026-11-27T10:00:00.000Z`. Stored as sent. `-00:00` means an unknown offset, so it is rejected. |
| `platform` | string | Not empty, such as `javascript`. |
| `sdk` | object | `name` and `version`, both non-empty strings. |
| `exceptions` | array | 1 to 5 exceptions; see [Exceptions](#exceptions). |

The server identifies an Event by its Project and its `event_id`. Sending the same `event_id` again gets `202` without counting the Event twice, so an SDK can retry safely.

### Optional fields

| Field | Type | Rules |
| --- | --- | --- |
| `level` | string | `fatal`, `error` or `warning`. Default `error` when absent; an empty string is rejected. |
| `handled` | boolean | Whether the host application caught the error. |
| `mechanism` | string | How the SDK captured the Event: `onerror`, `unhandledrejection`, `uncaughtException` or `manual`. An empty string is rejected. |
| `environment` | string | The Environment, such as `staging`. Default `production`, also when empty. |
| `release` | string | The Release, such as `checkout@1.4.2`. |
| `tags` | object | At most 50 tags, each a string value of at most 200 characters. |
| `contexts` | object | `runtime`, `os` and `browser`, each an object of string values, such as `{"name": "node", "version": "22.11.0"}`. |
| `request` | object | The HTTP request being served: `url` and `method`, both strings. No headers, cookies or body. |
| `user` | object | The User: `id`, a string of 1 to 200 characters, assigned by the host application. Required when `user` is present. |
| `extra` | object | Any JSON object, at most 16384 bytes serialized as compact JSON. |
| `breadcrumbs` | array | At most 100 Breadcrumbs; see [Breadcrumbs](#breadcrumbs). |
| `group_key` | array | A Custom Group Key: 1 to 10 strings of 1 to 200 characters. It replaces the Group Key the server would compute. |

### Exceptions

`exceptions` goes from the outermost exception to its cause: `exceptions[1]` is the cause of `exceptions[0]`, and so on.

| Field | Type | Rules |
| --- | --- | --- |
| `type` | string | Required, not empty, such as `TypeError`. |
| `message` | string | At most 8192 characters. |
| `frames` | array | At most 100 frames, parsed by the SDK. When a stack is longer, the SDK SHOULD drop the frames in the middle. |
| `raw_stack` | string | The stack trace as the runtime printed it. |

A thrown value that is not an error, such as `throw "x"`, or a muted cross-origin error (`Script error.`), is sent with a generic `type`, such as `Error`, the value as `message`, and no frames.

Each frame is an object whose fields are all optional:

| Field | Type | Rules |
| --- | --- | --- |
| `function` | string | The function name; empty or absent if anonymous. |
| `filename` | string | The file or URL of the code. |
| `lineno` | integer | From 1; `0` or absent means unknown. |
| `colno` | integer | From 1; `0` or absent means unknown. |
| `in_app` | boolean | Whether the frame is an In-app frame. Absent means the SDK did not tell. |

### Breadcrumbs

`breadcrumbs` goes from the oldest Breadcrumb to the newest.

| Field | Type | Rules |
| --- | --- | --- |
| `timestamp` | string | Required; an RFC 3339 date in UTC with milliseconds, like the Event's. |
| `type` | string | Required, not empty. Free; `navigation`, `http`, `console`, `ui` and `custom` are suggested. |
| `message` | string | At most 1024 characters. |
| `data` | object | Any JSON object. |

## Redaction

Before an Event is stored, the server replaces its sensitive values with `"[redacted]"`, by the rules of [`redaction.md`](redaction.md). It never rejects an Event for holding them. SDKs SHOULD apply the same rules before sending.

## Grouping

The server groups equivalent Events into one Issue by their Group Key, after Redaction. An SDK only takes part through `in_app`, which the server uses as sent, and the Custom Group Key `group_key`, which replaces the computation. Version 1 of the computation takes, for each exception from the outermost to its last cause, its `type` and its In-app frames as `function` and `filename`, never `lineno`, `colno` or `message`:

- `filename` loses its scheme, host, query and fragment, bundler hashes become `<hash>`, and only its last two path segments count. A bundler hash is a part of a segment, between `.` or `-`, of at least 8 letters, digits or `_`, with a digit or only hex digits: `https://cdn.example.com/assets/js/app-3f2a1b9c.js` becomes `js/app-<hash>.js`.
- Consecutive equal frames, as in recursion, count once; frames without `filename` are dropped; an anonymous `function` counts only its `filename`.
- Without In-app frames, every frame counts. Without frames, the `type` and the `message` count, with ids, numbers, emails, URLs and quoted literals replaced by placeholders such as `<uuid>` and `<num>`.

Minified code without source maps groups by its minified names, so an Issue may split across Releases.

## Responses

A batch is accepted only once it is durably stored:

```
202 Accepted
{"accepted": 3}
```

`accepted` counts every Event of the batch, duplicates included. Every error has this body:

```json
{"error": {"code": "invalid_event", "message": "the batch has invalid Events", "details": [{"index": 1, "message": "sdk.name and sdk.version are required"}]}}
```

`code` is stable, snake_case, and what an SDK programs against. `message` is English, for debugging, and MAY change. `details` is always an array, empty if there is nothing to add.

| Status | `code` | When |
| --- | --- | --- |
| 400 | `invalid_event` | The body or an Event breaks this protocol. |
| 400 | `ingest_key_conflict` | The header and the query parameter carry different Ingest Keys. |
| 401 | `ingest_key_missing` | No Ingest Key. |
| 401 | `ingest_key_invalid` | The Ingest Key is unknown or revoked. |
| 413 | `payload_too_large` | The body or an Event exceeds a [size limit](#size-limits). |
| 415 | `unsupported_media_type` | The `Content-Type` or `Content-Encoding` is not supported. |
| 429 | `rate_limited` | The Project sent more Events than its rate limit allows. Comes with `Retry-After`. |
| 503 | `ingest_overloaded` | The server is overloaded. Comes with `Retry-After`. |
| 503 | `shutting_down` | The server is shutting down. |
| 500 | `internal_error` | The server failed. |

`Retry-After` is always a whole number of seconds.

## Retries

An SDK MUST follow these rules:

- Retry only after `429`, `503` or a network failure. Any other response is final: the SDK drops the batch.
- Wait the `Retry-After` of the response. Without one, wait an exponential backoff with jitter, such as a random delay between 0 and `min(60 s, 1 s × 2^attempt)`.
- Give up on a batch after a cap of retries, such as 5.
- After a `429`, pause every send to the server, not just the rejected batch, until `Retry-After` has passed.
- Keep the same `event_id` on every retry of an Event.

## Fixtures

[`fixtures/valid/`](fixtures/valid/) and [`fixtures/invalid/`](fixtures/invalid/) hold one request body per file:

```json
{
  "description": "What the fixture shows",
  "code": "invalid_event",
  "index": 0,
  "body": {"events": ["…"]}
}
```

- `body` is the request body to send.
- A valid fixture MUST get `202`.
- An invalid fixture MUST get `400` with `code`. When one Event breaks the protocol, `index` is the only index in `details`; without `index`, `details` is empty.
- Every valid body matches `event.schema.json#/$defs/batch`, and every invalid one breaks it, except those with `beyond_schema`, which explains the rule the schema cannot express.

[`scripts/generate_fixtures.py`](../../../scripts/generate_fixtures.py) writes the fixtures. The JSON files are the contract; edit the script and run it to change them.
